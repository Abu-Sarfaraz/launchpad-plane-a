ভিবে কোডিং ও প্রারম্ভিক ইমপ্লিমেন্টেশনের ৭টি মারাত্মক ত্রুটি (Gap Analysis)

ভিডিওর ডেমো দেখে সরাসরি AI এজেন্টের মাধ্যমে কোড বানালে যে ৭টি টেকনিক্যাল ও সিকিউরিটি ঘাটতি তৈরি হয়।

CRITICAL DEFECT #1 Math & Layout Rendering

গাণিতিক সিম্বল ও LaTeX ভগ্নাংশ ভেঙে যাওয়া (KaTeX Breakage)

ক্যামব্রিজ ম্যাথ পরীক্ষায় প্রচুর ভগ্নাংশ, স্কয়ার রুট ও ম্যাট্রিক্স চিহ্ন থাকে। সরাসরি সাধারণ HTML বা Canvas দিয়ে PDF বানালে প্রিন্টের সময় গাণিতিক ইকুয়েশন এবং ফ্র্যাকশন লাইন উধাও হয়ে যায়।

CRITICAL DEFECT #2 PDF Pagination Overflow

PDF পেজ ব্রেক এবং প্রশ্ন কেটে যাওয়া (Uncontrolled Overflow)

একটি ৪ নম্বরের প্রশ্নের অর্ধেক অংশ পেজ ১-এ এবং উত্তর লেখার ফাঁকা জায়গা পেজ ২-এ চলে যাওয়ার ঝুঁকি। সঠিক CSS `@media print` ও সাইজ হিসাব না থাকলে পেপার নষ্ট হয়।

CRITICAL DEFECT #3 Data Security & RLS

Row-Level Security (RLS) বিহীন ডেটাবেজ ও পাইরেসি

অটো-জেনারেটেড কোডে Supabase টেবিলে RLS অন না থাকলে যে কেউ API দিয়ে পুরো প্রশ্ন ব্যাংক, শিক্ষকদের কোচিং লোগো এবং জেনারেট করা পেপার চুরি করতে পারে।

CRITICAL DEFECT #4 Mark Scheme Desync

প্রশ্ন সোয়াপিংয়ের পর মার্ক স্কিম অসমঞ্জস্যতা (Desync Bug)

১-ক্লিকে প্রশ্ন সোয়াপ করার সময় প্রশ্নপত্রের কন্টেন্ট পাল্টালেও শেষ পৃষ্ঠার Mark Scheme না বদলানোর মারাত্মক স্টেট ম্যানেজমেন্ট বাগ।

CRITICAL DEFECT #5 Geometry Image Blur

জ্যামিতি চিত্রের ঝাপসা প্রিন্ট (Low DPI Geometry Rasterization)

পাস্ট পেপারের ডায়াগ্রাম (Vectors, Trigonometry) লো-রেজুলেশন র্যাস্টার ফরম্যাটে থাকলে প্রিন্ট আউট নিলে পিক্সেল ফেটে অস্পষ্ট হয়ে যায়।

CRITICAL DEFECT #6 Context & Quota Exhaustion

Antigravity কোটা ও Stitch API এক্সহস্টন

ছোটখাটো স্টাইলিং পরিবর্তনের জন্য বারবার Stitch MCP দিয়ে নতুন ডিজাইন জেনারেট করলে প্রতি মাসের ৫০-টি Gemini Pro রিকোয়েস্ট কোটা ১ দিনেই শেষ হয়ে যায়।

প্রি-ফ্লাইট টেকনিক্যাল সমাধান ও হার্ডেনিং (Hardened Remedies)

সকল সনাক্তকৃত ত্রুটি দূর করে প্রোডাকশন-গ্রেড প্ল্যাটফর্ম বানানোর সুনির্দিষ্ট ইঞ্জিনিয়ারিং সমাধান।

১. নিখুঁত গাণিতিক ইকুয়েশন ও KaTeX রেন্ডারিং ইঞ্জিন

FIXED

আমরা ক্লায়েন্ট ও সার্ভার উভয় স্থানেই KaTeX ম্যাথ ইঞ্জিন ব্যবহার করব। প্রতিটি গণিত প্রশ্ন LaTeX ফরম্যাটে (e.g. \frac{a}{b} \cdot \sqrt{x^2+y^2}) ডেটাবেজে সংরক্ষিত থাকবে এবং PDF জেনারেট করার সময় ভেক্টরাইজড রেন্ডারিং নিশ্চিত করবে।

// Solution: Server-side KaTeX rendering to high-DPI Canvas prior to Puppeteer PDF print

২. এটমিক প্রশ্ন সোয়াপিং ও মার্ক স্কিম সিঙ্ক

৩. পেজ ওভারফ্লো প্রতিরোধ ও অটোমেটিক স্পেসিং

PHASE 1: Workspace Scaffolding & Design DNA

Read `/DESIGN.md` and `/rules/AGENTS.md`. Connect to the `stitch` MCP server, verify project screens, and scaffold a Next.js 15 (App Router, React 19, TypeScript, Tailwind CSS, Radix UI) workspace. Compile all `/DESIGN.md` tokens into `tailwind.config.ts` CSS variables.

PHASE 2: Database Schema & RLS Migrations

Using the `supabase` MCP server, execute `apply_migration` to create tables: `profiles`, `institutes`, `questions_bank`, `mock_papers`, and `generated_pdfs`. Enable strict ROW LEVEL SECURITY (RLS) policies scoped to `auth.uid()`. Generate TypeScript types into `/src/types/database.types.ts` and run `get_advisors`.

PHASE 3: Auto Generator & Swap UI Engine

Build the Auto Mock Generator modal supporting Target Marks (25, 50, 100, Custom), Time selection, Chapter checklists, and Difficulty Curves (Standard CAIE, Foundation, A* Challenger). Build the 1-Click Question Swap engine ensuring atomic mark scheme updates.

PHASE 4: KaTeX Engine, Branding & Vector PDF Export

Integrate KaTeX math rendering engine. Build the Branding & Layout Settings modal allowing coaching name, subtitle, logo upload, student header, and official Cambridge cover page toggle. Implement vector PDF export with official mark schemes attached at the end.

PHASE 5: Playwright QA, GitHub PR & Vercel Ship

Run `playwright` MCP server across Desktop (1440px), Tablet (768px), and Mobile (390px) viewports to verify paper layout and forms. Commit code using `github` MCP server to a feature branch, create PR to `main`, and trigger production deployment via `vercel` MCP.
